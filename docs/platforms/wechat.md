# 微信接入

| 路线 | 主体要求 | 能私聊 | 能进群 | 合规 | 适合 |
|---|---|---|---|---|---|
| A. 公众号 | 个人/企业可注册 | ✅ 关注者 | ❌ | ✅ | 对外服务 |
| B. 企业微信 | 企业/组织 | ✅ 内部成员 | ✅ 内部群 | ✅ | 团队内部 |
| C. 个人号 hook | 无 | ✅ | ✅ | ❌ | 自用，风险自负 |
| D. iLink Bot（本仓库） | 需配对 | ✅ | ⚠️ 有限 | 灰色 | 个人自用助手 |

---

## A. 公众号

- 微信公众平台注册，配置服务器 URL + Token（或 AstrBot 的公众号适配器）
- 限制狠：被动回复 5 秒超时、客服消息 48 小时窗口、主动推送要模板消息
- 适合：问答、客服；不适合：日常闲聊（延迟太明显）

## B. 企业微信

- 建应用 → 拿 CorpID / Secret / AgentId → 配置接收消息服务器
- 群机器人可用 webhook，但只能发不能收
- 适合：内部工具、告警；不适合：当私人伙伴

## C. 个人号 hook

- gewechat / wechaty 一类，扫码登录网页协议或注入 PC 客户端
- 能力最全（能私聊、能进群、能发表情），但**违反微信用户协议**，封号是常态
- 要做的准备：小号、备用号、消息限速、别群发

## D. iLink Bot

- 微信侧的 bot 接口，靠扫码配对拿到 token，Hermes 的 `weixin` 适配器就吃这个
- **硬约束（最容易踩）**：bot 主动发消息要求对方最近给 bot 发过消息，否则

```
iLink sendmessage session not ready: ret=-2 ... prepare failed
```

- 表现：定时任务的推送会因为你长时间没说话而失败；你随便发一句就恢复
- 应对：
  - 定时任务的 `failure_deliver` 设成 `local`，别反复重试刷屏
  - 有重要主动推送时，先发一条消息把会话激活
  - 长文本要分块（平台有单条长度上限），图用 MEDIA 路径

---

## 微信侧通用注意

- **不要群发**：频率一高就会被限制，表现是静默失败
- **图片/文件**：走本地路径或 CDN，别塞 base64 进正文
- **语音**：要先转码（silk/amr），否则对方听不了
- **富文本**：微信不渲染 Markdown 复杂语法，表格会散；要么纯文本，要么发图
- **会话是资源**：每个 peer 的会话都可能过期，设计上要假设「随时会掉」

## 排查顺序

1. 能不能收到你的消息（入站链路）
2. 能不能回（出站链路）——错误里看 `ret` / `errcode`
3. 长文本/图片是否触发限流
4. 平台侧 token 是否过期（重新配对）
