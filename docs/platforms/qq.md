# QQ 接入

三条路，能力、合规性、风险完全不同。

| 路线 | 原理 | 能进群 | 合规 | 封号风险 | 适合 |
|---|---|---|---|---|---|
| A. QQ 官方机器人开放平台 | 官方 API | 群/频道有限能力 | ✅ | 无 | 企业、公开服务 |
| B. OneBot 注入（NapCat / SnowLuma） | 往真 QQ 客户端注入 hook，翻译成 OneBot 11 | ✅ 完整 | ❌ 灰色 | 高 | 自用、私群 |
| C. 协议库（Lagrange 等） | 自己实现 QQ 协议 | ✅ | ❌ 灰色 | 更高 | 折腾党 |

绝大多数「群里的大肥鱼」都是 B。

---

## A. 官方机器人开放平台

- 在 q.qq.com 建应用，拿到 AppID / AppSecret / Token
- 机器人只能被 @ 或指令触发，能力受平台限制（不能主动私聊陌生人、群发受限）
- 适合：客服、公告、公开频道
- 不适合：想让它像群友一样自由插话

## B. OneBot 注入

协议端负责登录 QQ 并暴露接口，框架负责聊天逻辑：

```
QQ 客户端 ←注入/挂载→ NapCat 或 SnowLuma
                          ↓ OneBot v11 (HTTP / 正向 WS / 反向 WS)
                     AstrBot / NoneBot2 / 自写服务
                          ↓
                     大模型 API
```

**关键概念**

- **正向 WebSocket**：协议端开服务，框架去连（本仓库配置用的是这种）
- **反向 WebSocket**：框架开服务，协议端去连
- **HTTP**：一问一答，最简单但没事件推送

**必须注意**

- 一个 QQ 号只能被一个协议端登录
- 群消息要开 `reportSelfMessage` 才能把「你自己说的话」计入上下文
- 掉线不会自愈，要有重连或定时重启
- 用**小号**，别用主号赌

## C. 协议库

不依赖官方客户端，直接实现协议。省资源、能跑在无头服务器，但版本跟进滞后、更容易被判异常。除非你清楚自己在做什么，否则优先 B。

---

## 群聊行为要点

- 唤醒：@ / 引用 / 喊名字，三者至少配一种
- 频率：宁可少说。默认不回，被点名或多轮相关才开口
- 表情：真 QQ 表情要按平台的表情编号体系发，两套编号体系不通用
- 认人：群昵称要注入到上下文，否则分不清谁在说话
- 引用：只在「指向的不是最新一条」时才引用，别每条都引

## 排查顺序

1. 协议端 WebUI 能不能登录、在线
2. OneBot 端口通不通（`curl` 一下 / `/get_status`）
3. 框架日志有没有收到事件
4. 模型 API 有没有返回
5. 发送失败看返回码：频率限制 vs 会话失效 vs 权限不足
